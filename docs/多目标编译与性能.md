# 多目标编译与性能

五个库（Inkslab.Transactions、Inkslab.Linq、MySql、SqlServer、PostgreSQL）均发布以下资产：

| NuGet 目标 | C# 语言版本 | 性能实现 |
|---|---|---|
| netstandard2.1 | 9.0 | 保留兼容实现 |
| net6.0 | 10.0 | 分页 SQL 使用插值字符串处理器 |
| net8.0 | 12.0 | 以上优化，加上参数匹配正则源码生成 |
| net10.0 | 14.0 | 以上优化，加上字段分隔的 Span 集合表达式 |

语言版本在 `Directory.Build.props` 中按目标固定，不使用 `latest` 或预览版本。
完整构建需要 .NET 10 SDK。NuGet 根据消费项目的目标框架选择 DLL，消费方无需使用相同的 C# 语言版本。
`LibraryFrameworks` 仍可覆盖库目标，`TestFrameworks` 可覆盖测试目标。
`global.json` 与 Inkslab 一致，固定 .NET SDK 10.0.401 并允许同功能带内的最新补丁；不使用预览 SDK。

## 条件编译的性能路径

### 分页 SQL：NET6_0_OR_GREATER

三个数据库的 `CorrectSettings.ToSQL` 使用 `string.Create(CultureInfo.CurrentCulture, $"...")`。
C# 10 的插值字符串处理器将字符串和整数写入结果构造过程，省去原有的
`StringBuilder` 对象及其字符缓冲区；旧目标继续编译原实现。

SQL 的空格、分页分支和当前文化的数值格式均通过回归测试验证。
所有目标框架均在 `sql` 为 null 或空字符串时抛出 `ArgumentException`。
`orderBy` 为 null 或空字符串时，跳过排序及其前置空格，不赋为空字符串，避免因缺少排序生成连续两个空格。
回归测试覆盖无效 SQL、缺省排序及不同分页分支。
这里显式使用当前文化，避免把既有格式语义改为不变文化。

### 参数匹配：NET8_0_OR_GREATER

`CommandSql` 使用 `GeneratedRegex` 生成专用参数匹配器。
匹配器随程序集进入 NuGet 包，首次使用时无需通过 `RegexOptions.Compiled` 动态生成匹配器 IL。
匹配模式、参数边界和 `CultureInvariant` 选项保留，测试覆盖 Unicode 参数和土耳其文化。
该优化的确定收益是移除首次使用时的正则动态编译；没有据此宣称整体查询吞吐提升。

### 字段分隔：NET10_0_OR_GREATER

`RepositoryRouter.AnalysisFields` 使用 `text.Split((ReadOnlySpan<char>)[',', ' '])`。
集合表达式为常量分隔符生成只读 Span，调用现代框架的 Span 重载，省去临时 `char[]`。
拆分结果仍然分配，逗号和空格仍保留原有分隔语义。
未启用此分支的旧目标继续使用原来的 params 数组调用。

共享源文件还需支持 C# 9/10，因此 `.editorconfig` 不强制将所有集合改成 C# 12 集合表达式；
原有集合初始化器规则和其他代码规范仍生效。

## 分配量验证

2026-10-26，Windows x64，SDK 10.0.401，Release；分别在 .NET 6.0.36、8.0.29、10.0.12 上运行。
对生产适配器的 `ToSQL` 和原 `StringBuilder` 实现分别预热 10,000 次、执行 100,000 次，
用 `GC.GetAllocatedBytesForCurrentThread` 的差值除以次数，记录平均 B/次。
两种实现先校验生成的 SQL 相等，循环保存返回值以保留实际调用结果。

输入为 `sql = "SELECT id FROM users"`、`orderBy = "ORDER BY id"`、`take = 20`、`skip = 10`。
三个运行时测得相同结果：

| 适配器 | 原实现 B/次 | 新实现 B/次 | 减少 |
|---|---:|---:|---:|
| MySQL | 288 | 112 | 61.1% |
| PostgreSQL | 312 | 128 | 59.0% |
| SQL Server | 384 | 168 | 56.3% |

.NET 10 上以 `"Name,Price"` 为输入，对比显式 `new char[] { ',', ' ' }` 与 Span 集合表达式：
前者 136 B/次，后者 104 B/次，每次减少 32 B。该结果包含拆分结果的字符串和数组分配。

以上是指定输入的分配量对比，不是端到端数据库吞吐量或耗时基准。

## 构建、测试和打包

```powershell
dotnet build -c Release

# 运行兼容性回归；需要安装 .NET 6/8/10 运行时。
dotnet test tests/Inkslab.Linq.Tests -c Release --filter FullyQualifiedName~FrameworkCompatibilityTests

# 仅验证指定目标。
dotnet test tests/Inkslab.Linq.Tests -c Release -f net8.0

# 完整发布验证：还原、Release 构建、全部测试、打包并校验五个包。
.\build.ps1

# 数据库不可用时显式跳过测试；仍执行构建、打包及包内容校验。
.\build.ps1 -SkipTests

# 已还原依赖时跳过还原；只构建和测试，不打包。
.\build.ps1 -SkipRestore -CreatePackages $false
```

测试默认覆盖 net6.0/net8.0/net10.0；依赖真实数据库的测试仍需要配置可用连接。
构建产物和 NuGet 包位于项目内的 bin/obj 和 `.nupkgs`。脚本从仓库根目录执行各步骤，任何命令失败立即停止，并恢复调用者目录。
打包使用刚生成的 Release 产物，保留包输出目录中的历史版本；不允许 Debug 打包。
打包后自动校验当前版本五个包的标识、四个框架的 DLL/XML、依赖组及 README、许可证、图标和模块文档。

2026-10-27 发布配置验证：完整解决方案 Release 构建无警告、无错误；选定的 257 个无数据库测试在三个运行时各通过一遍，共 771 次，未运行真实数据库集成测试。
五个 `2.0.0` 包均已本地生成，通过包标识、版本、四个框架 DLL/XML、依赖组及文档校验；核心库依赖 `Inkslab 2.0.1`，尚未上传 NuGet。

## SQL 调试日志

同步、异步、批量命令和多结果集执行统一调用 `LogCommandIfDebug`，由该方法内部判断
`ILogger.IsEnabled(LogLevel.Debug)`；关闭 Debug 时不格式化 SQL。
异步查询在实际枚举时记录，创建查询对象时不记录，重复枚举每次各记录一次。

PostgreSQL 的 COPY 和事务内批量 INSERT 也在执行前记录命令，批量 INSERT 日志包含参数值。
通过 DI 注册的 `PostgreSQLBulkCopyFactory` 将 `ILogger<PostgreSQLBulkAssistant>` 传给助手；
手动创建助手时可使用带日志参数的构造函数。旧构造函数继续可用，默认使用空日志记录器。
MySQL、SQL Server 的原生批量复制调用驱动协议，不在框架内构造 SQL 文本。
